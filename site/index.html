Every care instruction Alexa says can be traced back to the page it came from.

CareLoop is an add-on for Alexa+ that turns a clinician's plan into tasks the patient approves and understands, family members help with from their own speaker and phone, and a clinician can trust.

Built for the Amazon Developer Hackathon 2026, Alexa+ track. A demo with synthetic data, not medical advice, and not an Amazon product.

Alexa+ remembers. CareLoop proves.

In the demo, Sam's phone is a simulated CareLoop app. Alexa+ add-ons have no documented way to push to a phone, so a real CareLoop app would get these notifications from CareLoop's own server. Maya can remove Sam by voice at any time, and his access ends on his next request.

Approved is not the same as understood.

After Maya approves her medicines, she can ask Alexa to check she understood them. CareLoop asks her to say each one back. Alexa only passes on her words: the server checks every answer against the approved, cited line, and a miss is answered by reading that line, never by explaining it.

  • Checked in code

    "Every 8 hours" and "three times a day" are the same answer. A wrong one gets a second try; then the plan is read back and the check moves on.

  • Read back, never explained

    Alexa says what the approved line says, in its own words. It never gives a reason or advice. Three misses in a row leave the rest for the clinician.

  • Only the value is kept

    CareLoop stores "8:00 AM", never Maya's words. Sam can't see the results. Her clinician sees them in the visit handoff.

What CareLoop never does

The limits are part of the product. They are what make it safe to put on a kitchen speaker.

  • Diagnose, prescribe, change a dose, or interpret a trend.
  • Explain a medicine during a teach-back. It reads the approved line back, and nothing else.
  • Raise a suggestion it can't trace to one of the patient's own records.
  • Invent an instruction, a number, or an alert threshold.
  • Read a symptom, a value, or a medicine aloud on a shared speaker, or put one on a lock screen.
  • Add an instruction twice because the same page was shared twice.
  • Treat a missed check-in as "fine". The summary says it wasn't recorded.
  • Claim to monitor for emergencies. Crisis words get the emergency number, 988 in the US.
  • Share anything without the patient's confirmed consent, which she can withdraw at any time.

See it running

Without Alexa+ preview access, we built a browser simulator that behaves like Alexa+ in front of the same MCP server: two devices, Sam's phone, account linking, local voice, and a live MCP inspector.

  • 100% of expected items found when reading the synthetic prescriptions (typed, scanned and photographed, 3 runs each), with 0 invented numbers.
  • 70 spoken scenarios, run 3 times each with a hosted model as the planner: 207 of 210 passed, and the one scenario that failed had an out-of-date expectation. It now passes.
  • 420 automated tests, including complete conversations against a running server, a check that every card on the patient's screen carries its source, and Sam's phone end to end.
  • 32 MCP tools covering plans, documents, check-ins, teach-back, suggestions, family, consent, handoffs and data rights.

For developers

A standard MCP server over Streamable HTTP. Any MCP client can use it; in production, Alexa+ brings its own model.

# Python 3.12+, uv, and optionally Ollama
git clone https://github.com/Ghost-141/CareLoop.git
cd CareLoop
uv sync --extra dev --extra alexa-sim --extra voice \
        --extra intake --extra ocr
cp .env.example .env   # optional: local model and voice
uv run pytest -q
scripts/run_alexa_demo.sh
  • Voice-safe results. Every tool returns one sentence safe to say aloud, plus opaque references. Private detail goes to a sandboxed MCP Apps screen.
  • MCP elicitation. Check-ins, guided reviews, consent and teach-back ask their own follow-up questions mid-call. Teach-back answers are checked by the server, not the model.
  • Your choice of model. The simulator's planner and document reader use a local Ollama model, any OpenAI-compatible API, or a scripted planner. OCR, models and voice run on your machine by default. Code checks every proposed item, and lines that read like commands to an AI are set aside.
